# 도면 없는 자율 3D 스캔: BIM 기반 스캔 계획을 학습한 4족보행 로봇

> **건설 현장은 매일 바뀌어서 BIM대로 짠 스캔 계획이 금방 어긋난다. 우리 4족 로봇(Unitree Go2 + VLP-16)은 BIM으로 미리 배워 두고, 현장에서는 보이는 대로 판단해 3D 스캔을 완성한다. BIM이 아예 없는 건물에서도 마찬가지다.**

- 연구 목표 정리 문서: [docs/3DOG_연구목표_정리.docx](docs/3DOG_연구목표_정리.docx)

## 한눈에: 최종 목표 → 기존 연구 → 우리 차이

### 최종 목표

**현장에서 BIM에 의존하지 않고, 4족 로봇이 혼자 3D 스캔을 완성한다. BIM과 다른 현장에서도 BIM 기반 계획 이상으로.**

### 왜 필요한가: 현장은 BIM과 다르다

| 경우 | 예시 | 비중 |
|---|---|---|
| **B. BIM과 현장이 다르다 (메인)** | 공사 중 현장(매일 바뀜), 자재·가설물 적치, 시공 오차 | 공사 중 현장은 사실상 전부 |
| A. BIM이 아예 없다 | 노후 건물, 오래된 인프라, 리모델링 대상 | 기존 건물 대부분 |

BIM 기반 스캔 계획은 현장이 BIM과 다르면 막히거나 놓치는 곳이 생긴다. 우리 로봇은 BIM으로 배워 두되, 현장에서는 라이다로 본 것만으로 판단한다.

### 기존에는 이런 연구를 했다

| 기존 연구 | 한 일 | 한계 |
|---|---|---|
| **BIM 기반 스캔 계획** (연구실 Park 2023) | BIM으로 4족 로봇의 스캔 위치·순서를 최적화, 측량사보다 효율적 | **현장마다 BIM이 필요.** 도면이 없거나 현장과 다르면 못 씀 |
| **강화학습 자율탐사** (ARiADNE 2024, HEADER 2025, GRATE 2025) | 도면 없이 탐사하는 정책 학습 | **2D 지도만** 채움. 회전은 공짜로 가정 |
| **3D 능동 매핑** (GLEAM 2025, MAGICIAN 2026) | 3D 커버리지를 높이는 시점 선택 | **떠다니는 카메라** 가정. 실제 로봇 이동 제약 없음 |
| **도면 → 맵 → 탐사 학습** (HouseExpo 2019) | 평면도 3만여 장으로 탐사 학습 | **2D**, 보상은 새로 본 영역 |

### 우리는 이게 다르다

1. **BIM을 현장이 아니라 학습에만 쓴다.** BIM으로 계산한 최적 스캔 계획을 탐사 정책의 학습 목표로 쓰고, 현장에서는 라이다만 쓴다 → 도면 없는 현장에서도 동작
2. **2D 지도가 아니라 3D 스캔이 목표다.** 기울인 3D 라이다로 벽·천장 커버리지를 높인다 (2D 97% 완료 시 3D는 77%뿐이었다)
3. **4족 로봇의 움직임을 학습에 넣었다.** 멈춤·회전·보행 시간을 보상과 입력에 반영한다 (GRATE는 학습 후 보정)

"BIM으로 계산한 최적 스캔 계획을 학습 목표로 쓰는" 연구는 이번 조사에서 찾지 못했다. 자세한 비교는 아래 [기존 연구와의 차이](#기존-연구와의-차이-가장-중요)와 [docs/관련논문.md](docs/관련논문.md).

| | 내용 |
|---|---|
| **방법** | BIM을 2.5D 학습 맵으로 바꿔 최적 스캔 계획을 계산하고, 탐사 정책이 그 계획을 따라 배운다 |
| **검증** | Isaac Sim 속 백양누리 → 실제 백양누리 (PRAXIS) |

## 정량 목표 (백양누리 한 층)

1. **핵심 · 강건성:** BIM에 없는 장애물(자재, 가설벽)이 있는 현장에서 BIM 기반 계획보다 3D 커버리지가 높거나 스캔 시간이 짧다
2. **효율:** BIM과 같은 현장에서는 BIM 기반 계획 대비 스캔 시간 차이 15% 이내 (BIM 없이 BIM만큼)
3. **완성도:** 3D 벽·천장 커버리지 90% 이상

수치는 베이스라인 측정 후 확정한다.

## 지금 상태와 다음 할 일 (팀원용)

1단계(BIM → 2.5D 맵 변환)는 끝났고, BIM 기반 계획 시연도 했다. 남은 2단계는 Ubuntu PC에서 **2.5D 환경(`ariadne3d`)으로 탐사 정책을 학습**시키는 것이다. Isaac Sim은 느려서 학습에는 쓰지 않는다. 학습이 끝나면 3단계부터 **Isaac Sim에 백양누리를 올려서 Go2로 시험**한다.

| | 2단계 (학습) | 3~5단계 (시험) |
|---|---|---|
| 프로그램 | 2.5D Python 환경 (`ariadne3d`) | Isaac Sim |
| 로봇 | 점 + Go2 이동 시간 공식 | Go2 3D 모델 + 보행 정책 |
| 하는 일 | BIM 기반 계획을 따라 탐사 정책 학습 | 학습된 정책을 백양누리 등에서 시험 |
| 컴퓨터 | Ubuntu PC (CPU 위주, 수 시간) | Ubuntu PC (RTX 5090 필수) |

**2단계에서 실제로 할 일**

1. **patch 적용:** 메인 레포에 `git apply patches/3DOG_Go2-exploration.patch`
2. **새 보상 구현 (아직 안 만듦):** 탐사 정책의 선택이 BIM 기반 계획(`bim_expert.py`)의 다음 지점에 가까울수록 보상
3. **학습 실행:** Ubuntu PC에서 `ARIADNE_BIM_DIR=maps_train python driver3d.py --world bim`

## 기존 연구와의 차이 (가장 중요)

연구실의 BIM 기반 스캔 계획([Park et al., AutCon 2023](https://doi.org/10.1016/j.autcon.2023.104911))은 숙련 측량사보다 효율적이지만 **현장마다 그 건물의 BIM이 필요**하다.

**① BIM을 쓰는 방식이 다르다 (핵심)**

| 기존 | 한계 | 우리 |
|---|---|---|
| BIM 기반 스캔 계획 (Park 2023), BIM 내비게이션 ([GPP-BIM](https://tore.tuhh.de/entities/publication/e887db85-bec6-4504-8805-8b6398fa1fb7)) | 현장에서 BIM이 반드시 필요 | BIM은 **2.5D 학습 맵으로 바꿔 학습에만** 사용, 현장은 라이다만 |
| [HEADER (2025)](https://arxiv.org/abs/2510.15679): 정답 지도로 계산한 최적 경로를 따라 학습 | 2D 무작위 맵, 건설과 무관 | 정답 = **BIM**, 목표 = **건설 3D 스캔** |
| [HouseExpo (2019)](https://ar5iv.labs.arxiv.org/html/1903.09845): 건물 평면도 35,357장 → 2D 맵 → 강화학습 탐사 | 2D(높이 없음), 보상은 새로 본 영역 | 2.5D(높이 포함), 보상은 **BIM 기반 최적 스캔 계획** |

도면으로 맵을 만들어 학습하는 것 자체는 기존에도 있다. **"BIM으로 계산한 최적 스캔 계획을 탐사 정책의 학습 목표로 쓴다"**는 연결은 이번 조사에서 찾지 못했다.

**② 목표가 2D 지도가 아니라 3D 스캔이다**

| 기존 | 한계 | 우리 |
|---|---|---|
| ARiADNE, HEADER, GRATE (강화학습 탐사) | 바닥 2D 지도 완성 | 벽·천장 **3D 표면 커버리지** |
| GLEAM, MAGICIAN (3D 매핑) | 떠다니는 카메라 가정 | 실제 로봇 이동 제약 + 기울인 3D 라이다 |

실측 근거: 2D 탐사가 97% 끝났을 때 3D 표면은 77%뿐이었다.

**③ 4족 로봇의 움직임을 학습에 넣었다**

| 기존 | 한계 | 우리 |
|---|---|---|
| 대부분의 강화학습 탐사 | 회전은 공짜 (점 로봇) | 멈춤 → 회전 → 보행 **시간을 보상과 입력에 반영** |
| GRATE (2025) | 시간 최적화를 학습 후 보정으로 처리 | **학습 중에** 반영 |
| RAEM (2026, Go2) | 4족이지만 규칙 기반 | 학습 기반 |

**차이점이 아닌 것:** BIM → 맵 변환, 2.5D 환경(빠른 학습을 위한 수단), 강화학습과 ARiADNE 구조(그대로 사용), 정답으로 계산한 최적 경로를 따라 배우는 아이디어(HEADER). 우리 기여는 그 정답을 **BIM 기반 스캔 계획**으로, 목표를 **건설 3D 스캔**으로, 비용을 **4족 이동 시간**으로 바꾼 것이다.

**아직 증명 전인 것:** BIM 없이 BIM 계획에 가까운 성능, BIM과 다른 현장에서 BIM 계획보다 강건함 (4단계에서 확인).

## 무엇을 학습하나

전체 시스템 중 **"다음에 어느 지점으로 갈지 고르기" 하나**만 학습한다. 탐사 정책망(ARiADNE 구조)의 가중치를 학습한다.

```
입력: 로봇이 지금까지 라이다로 만든 지도 위의 후보 지점(노드), 노드마다
      위치 · 새로 보일 바닥 경계 · 방문 여부 · 회전 비용 · 새로 보일 벽·천장 양
        ↓
   [탐사 정책망]  ← 학습 대상
        ↓
출력: 주변 노드별 "다음에 갈 확률" → 가장 높은 노드로 이동
```

학습으로 익히는 요령: 새로 보일 게 많은 곳 먼저, 크게 도는 곳은 미뤘다가 한꺼번에, 방 단위로 끝내고 되돌아오지 않기, 천장이 높으면 너무 가까이 가지 않기.

| 학습하지 않는 것 | 담당 |
|---|---|
| 다리 움직임 | Isaac Lab에서 따로 학습 완료 |
| 지도 만들기, 위치 추정 | 점유 지도 / SLAM |
| 고른 지점까지 길 찾기 | A* 경로 계획 |

**지도는 두 개다.** 정책은 ②만 본다.

| | ① 2.5D 맵 (BIM에서 변환한 정답) | ② 로봇이 지금까지 본 지도 |
|---|---|---|
| 내용 | 건물 전체 | 라이다로 조금씩 채워짐 |
| 쓰임 | 가상 라이다 계산, BIM 기반 최적 계획, 커버리지 채점 | 탐사 정책의 입력 |
| 실제 현장 | 없음 | 진짜 라이다로 채움 |

## 왜 2.5D에서 학습하나

1. **빨라야 많이 학습한다:** Isaac Sim은 탐사 1번에 약 100초, 2.5D는 4,000번에 약 6시간(1차 학습 실측).
2. **정책은 "어디로 갈지"만 정한다:** 다리는 따로 학습했으니 물리 계산이 필요 없고, 이동 시간 공식이면 충분하다.
3. **2D로는 부족하다:** 기울인 라이다로 벽·천장이 어디서 보이는지 계산하려면 높이가 필요하다. 2.5D는 이를 계산할 수 있는 가장 가벼운 형태다.
4. **맵을 많이 만들기 쉽다:** BIM, 평면도, 절차 생성 모두 2.5D로 쉽게 만든다.

한계(돌출 구조, 계단·다층, 실제 물리)는 Isaac Sim 3D 시험과 실로봇 실증으로 확인한다. 기반 논문인 ARiADNE, HEADER도 가벼운 2D 맵에서 학습하고 3D 시뮬레이터와 실로봇에서 검증했다.

## 데이터 역할

| 데이터 | 역할 |
|---|---|
| 절차 생성 맵 (수천 개) | 학습 (양의 대부분) |
| 공개 BIM · 평면도 데이터(HouseExpo 등) · 연구실 다른 BIM | 학습 |
| **교수님 백양누리 BIM** | **시험** (학습에 쓰지 않음) |
| 창고 · 사무실 · 건설현장 Isaac Sim 환경 | 추가 시험 |

**백양누리 규칙:** 백양누리도 변환은 한다(Isaac Sim 시험장, 상한선 계산용 2.5D). 다만 학습 맵에는 절대 섞지 않는다.

```
maps_train/   공개 BIM, 평면도, 절차 생성 맵   ← 학습은 이 폴더만 (ARIADNE_BIM_DIR)
maps_test/    백양누리                          ← 시험 전용
```

설정 조정은 다른 시험 맵으로 하고, 백양누리는 마지막에 한 번 제대로 시험한다(백양누리에 맞춘 튜닝 방지).

### 1. BIM → 2.5D 학습 맵 변환 (완료)

- 한 층을 잘라 벽·기둥·가구를 0.4 m 격자에 투영하고, 바닥에서 0.05~0.7 m 높이에 무언가 있으면 막힌 칸으로 본다.
- 문은 열린 것으로 처리하고, 바닥과 천장이 모두 있는 칸만 실내로 본다. 떨어진 세대는 따로 저장한다.
- 결과: 공개 IFC 3개 → 맵 11장 ([figures/maps/](figures/maps/)).

### 2. 탐사 정책 학습 (계획 시연까지)

- 맵마다 BIM 기반 최적 스캔 계획을 계산하고, 탐사 정책이 ②(본 지도)만으로 그 계획을 따라 가도록 학습한다.
- 지금까지: BIM 기반 계획 코드(`bim_expert.py`)와 비교 시연. 남은 것: 새 보상 구현과 실제 학습(Ubuntu 학습 PC, 수 시간).

### 3. 백양누리 BIM → Isaac Sim 구축 (예정)

- IFC → 3D 메시 → Isaac Sim(USD). 단위(mm→m), 충돌, 문 열기, 유리 확인, 시험 구역 밖 막기.
- 정답: 2D 점유 지도, 3D 표면 정답, BIM 기반 계획 결과(상한선). 시험 구역은 실제 실증 구역과 같게 정한다.

### 4. Isaac Sim 백양누리에서 시험 (예정)

Go2 3D 모델(학습된 보행) + 학습된 탐사 정책이 BIM 없이 탐사한다.

| 비교 대상 | 역할 |
|---|---|
| BIM 기반 최적 계획 | 상한선 |
| frontier 탐사 | 기존 고전 방법 |
| 원본 ARiADNE · 1차 재학습 정책 | 기존 학습 방법 · 이전 단계 |

- 조건 ① BIM 그대로: 상한선에 얼마나 가까운가
- **조건 ② BIM에 없는 장애물 추가 (핵심 결과):** 공사 중 현장을 흉내 낸다. BIM 기반 계획은 원래 BIM으로 짠 경로를 따르므로 막히거나 놓치고, 우리 정책은 본 대로 대응한다. 여기서 BIM 기반 계획보다 낫다는 숫자가 나와야 이 연구의 주장이 성립한다.

### 5. 다른 환경에서 일반화 확인 (예정)

학습에 안 쓴 2.5D 맵 60장, NVIDIA 창고, 사무실 등, 공개 IFC 건물에서 같은 비교를 반복한다. 특히 **건설현장 디지털트윈**(9/8 면담에서 교수님이 언급한 RESMOS, Isaac Sim으로 가져올 수 있는지 확인 필요)은 실제 공사 중 현장에 가장 가까운 시험이다. 모든 환경에서 순위가 같으면 성공이다.

### 6. 실제 백양누리 실증 (PRAXIS, 예정)

- 실제 Go2 + VLP-16(15° 마운트) + Jetson Orin NX로 같은 구역을 BIM 없이 탐사한다.
- 정답은 연구실 TLS 스캔. TLS 대비 커버리지·오차, 4단계 시뮬레이션 결과와 비교(sim-to-real).
- 준비: Go2 구입, SLAM 연동, 마운트 제작, 안전교육.

## 이후 확장 (실생활 · 건설 현장)

```
사기설 (시뮬레이션)      →  PRAXIS (실제 건물)      →  이후 (현장 적용)
도면 없는 한 층 스캔        실제 백양누리 실증           다층·험지·공정 관리
```

**기술 확장**

| 확장 | 내용 |
|---|---|
| 다층 · 계단 | 층을 오르내리며 건물 전체 스캔 |
| 험지 | 자재·잔해가 있는 공사 현장 바닥 |
| 움직이는 장애물 | 작업자, 장비를 피하며 스캔 |
| 고정밀 스캐너 결합 | 정책이 고른 지점에서 멈춰 TLS로 정밀 스캔 (연구실 stop-and-go와 결합) |
| 여러 대 협업 | 로봇 여러 대가 나눠서 스캔 |
| 말로 지시 | "3층 기계실만 스캔해" (VLA 확장) |

**건설 현장 활용**

| 활용 | 어떻게 |
|---|---|
| **공정 관리** | 매주 로봇이 현장을 스캔 → BIM과 비교해 진척도 자동 계산. 공사 중 현장은 매주 BIM과 다르므로, 탐사는 BIM 없이 하고 비교할 때만 BIM을 쓰는 구조가 맞다 |
| 준공 실측 (as-built) | 완공 건물을 스캔해 실제 BIM 생성 (Scan-to-BIM) |
| 품질 · 시공 오차 검사 | 벽 수직도, 개구부 위치 등을 점군으로 확인 |
| 안전 점검 | 사람이 들어가기 위험한 구역 스캔 |

**건물 밖 (사회기반시설):** 도면 없는 노후 건물 디지털화, 터널·지하 구조물·댐 내부 점검, 재난 건물 내부 파악, 공장·창고 디지털트윈 유지.

> 지금은 한 층을 도면 없이 스캔하는 것부터 시작하지만, 이게 되면 **공사 중인 현장을 로봇이 매주 혼자 스캔해서 BIM과 비교하는 자동 공정 관리**로 확장할 수 있다.

## 한계 (현재)

- 시험 장소인 백양누리는 완공 건물이라 공사 중 현장을 그대로 보여주지 못한다. BIM에 없는 장애물을 추가하고, 가능하면 건설현장 디지털트윈에서도 시험해 보완한다.
- 2.5D라서 칸마다 높이가 하나다. 문 위 인방·보, 계단·다층은 표현하지 못한다.
- BIM 기반 계획은 단순 그리디라 진짜 최적은 아니다. 큰 맵에서는 경로가 지나치게 길어진다.
- 좁은 문(약 1 m)이 많은 건물에서는 탐사 그래프 노드 간격(2~4 m) 때문에 탐사가 일찍 멈추는 경우가 있다.
- ARiADNE 원본 코드의 라이선스 표기가 없어 메인 레포 공개 전 확인이 필요하다.
